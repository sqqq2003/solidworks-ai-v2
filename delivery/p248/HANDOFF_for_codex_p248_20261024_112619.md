## 3. 已知坑（务必给 Codex 看）

### 3.1 warm reuse（温复用）
- 机制：`SW_WARM_REUSE_PID=16564` 环境变量 + 操作员授权；`require_model_write` 在 `warm_reuse_authorized and warm_reuse_pid` 时放行（不要求 `verified_exclusive`）。
- **坑**：首次 attach（11:10）hook 还没 fire，`warm_reuse_authorized=False` → 生成被拒（即旧 accept 的 fail）。11:12、11:18 两次 attach 才 `True`。这是**授权时序/竞态**，不是代码缺陷；新跑前务必确认 hook 已授权（看 log 里的 `OPERATOR-AUTHORIZED warm reuse ... attached_existing=True`）。
- `verified_exclusive` 按设计保持 `False`（是 attached_existing，非独占），teardown 只允许 CloseDoc 本任务打开的文档。

### 3.2 CloseDoc identity（teardown 身份）
- `close_owned_document(lease, app, title)` 要求传入的 `app` 是 **lease 绑定的 app**：满足 `app is lease.app_for_recycle`，或 `id(app) == lease.app_handle_id`，或 `id(app) in lease.bound_app_ids`。
- 用 `_as_interface(module, raw, "ISldWorks")` 包出来的**类型化 wrapper 是新对象**，其 `id` 不在 `bound_app_ids` 里——除非显式 `lease.note_bound_application(app)`。
- 原始 bisect 的 bug：① 重新 `_connect_task_solidworks`（line 65-66）拿到 `raw2` 后重新包了一个**未注册**的 `app`，teardown 用这个 `app` 调 `close_owned_document` → 拒 `"application object is not the lease-bound SolidWorks session (app_handle_id / identity)"`；② 重新 connect 还会把已打开文档重枚举进 `foreign_titles`、重设 `app_for_recycle`。
- **修复（r3）**：connect 后只包一次 `app`，立刻 `lease.note_bound_application(app)`，之后打开/关闭都用同一个 `app`，不再 reconnect。`phase_a_close="closed_via_bound_app"` 证明修复可复现。
- 附带规则：在 prime connect 时**已经打开**的文档会被枚举进 `lease.foreign_titles`，之后 `note_owned_document` 会拒绝它（这是正确安全行为）。所以重跑验证请针对**当时未打开**的文档；r3 选 `p248_step0_warm_r2`（未被打开）避开了这个坑。当前遗留的 `p248_step0_warm *` 就是“打开态被当 foreign”的文档，不要强行框架内 CloseDoc。

### 3.3 EXIT=139
- 进程退出码 139 = 128 + 11（SIGSEGV 类），发生在 COM teardown / `pythoncom` 卸载 / OLEAUT32 阶段，**在零件与 DXF 已保存之后**。

- **不要把 EXIT=139 当成 step0 失败**：交付物（零件 + DXF + 日志）已完整。CI 若以此判红需改为“看交付物是否落地”而非退出码。
