### 关于编号口径（重要，避免误读）

日志里两条记录**编号基准不同**，已核对源码确认：

- `自动折弯成功：bends=%s` → 传的是 `tuple(index + 1 for index in bend_indices)`，**1-based**
- `auto bend rejected ... failed=%s` → 传的是 `error.bend_indices`，即 `BendRejectedError` 保存的**原始 0-based**
  （同类内部 0-based 亦见于 `bend_group_attempts` 的 `index_base=0` 字段；
  异常 message 里给用户看的才做 `index + 1`）

因此：

- 成功：**0-based 105、106** → 界面显示 **106、107**
- 拒绝：**0-based 107、108** → 界面显示 **108、109**

**与 TASK_STATUS 历史记录的「108/109 拒绝、2/4」完全一致，本次为复现，不是新缺陷。**

## 4. 新发现：释放槽重试轮未能执行（基础设施缺陷）

两次实机都在**扩槽重试轮之前**中断：

```
12:35:01,999 WARNING auto bend rejected attempt=1 relief_step=0 failed=(107,108) completed=2
12:35:02,017 INFO    生成钣金零件 … 释放槽级别=1
12:35:02,018 INFO    矩形释放槽扩大：级别=1 边长各+1.0mm 改动=1
12:35:02,019 ERROR   SolidWorks 创建钣金零件时出错
                     → sw_owned_launch._read_pid
                     → pywintypes.com_error: (-2147220995, '对象没有连接到服务器')
```

即：第一轮折弯结束后 SW 进程（PID 14340 / 44076）**已退出**，
`require_model_write → validate → _read_pid` 读 `GetProcessID` 时 COM 断连，
`generate_sheet_metal_with_relief_retries` 的 `step += 1` 扩槽轮**根本没有跑起来**。

影响：

- 本次两轮**均未取得「扩槽 +1.0mm 后是否 4/4」的实机证据**
- 因此**不能**用本次结果支撑或否定任何关于"槽深不足"的结论
- 产物目录为空，未生成 SLDPRT

> 注：历史上有 `p0_sheetmetal_accept_relief_deepen_p248.json` 表明扩槽曾执行过，
> 本次断连不等于"扩槽从未验证过"，但**本次重试链路未生效**是确定事实，需单独立项排查。
