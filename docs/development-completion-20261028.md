## 当前代码的主要不足

1. 界面的勾选结果与后台批量任务脱节，用户可能取消某件后仍生成它；K 因子、缩放与圆孔策略也未完整传递。
2. 数量匹配窗口过窄，旁边或下方的数量漏配后默认为 1；一条标注还可能被多件共享。识别值与人工确认值混淆。
3. 批量异常路径会把某些会话错误当作普通单件失败继续写入；中止后剩余件缺少明确统计。
4. 断点指纹只包括顶层 Python，子包 COM 适配修改可能没有使旧结果失效。
5. 参数来源、依赖、确认与候选清单缺少跨桌面/CLI/AI 的一致交换格式。
6. 原有稳定引用已有身份约束，但还缺少将解析观察值与预期几何签名比较的共用函数。
7. 技能融合计划留在本机文档，云端代码缺少可查询的 I01–I08 进度与验收边界。
8. 便携构建硬编码 Python 3.14 与 Tcl/Tk 9；模型与代码交付、模拟与工程验收仍需更明确区分。
9. 原生三视图、BOM、配合和运动均有未验证范围；不能通过新增“成功”字段补齐真实能力。

## 本轮代码入口与使用流程

以下命令是后续使用说明，编写本计划时没有运行。

```powershell
python work/review_batch.py prepare --source inputs/parts.dxf --output review-01.json
python work/review_batch.py parameter --manifest review-01.json --part profile-1 --key quantity --value 2 --actor reviewer --source-note "人工核对图纸件数" --output review-02.json
python work/review_batch.py parameter --manifest review-02.json --part profile-1 --key thickness --value 4 --actor reviewer --source-note "已确认板厚" --output review-03.json
```

其余参数通过同一 parameter 命令记录：radius、angle、k_factor、scale、hole_policy。最后再 select --include yes/no；必须对所有候选明确包含或排除，参数变更后重新确认选件。scale=1 表示不改外形；scale_all 表示孔槽随外形缩放；preserve_circle_diameter 仅保持圆孔直径，不泛化为任意槽宽不变。实际几何限制仍由现有 profile_edit 决定，不绕过不支持图形的拒绝逻辑。

```powershell
python work/review_batch.py select --manifest review-N.json --part profile-1 --include yes --actor reviewer --reason "已核对为目标零件" --output review-selected.json
python work/review_batch.py check --manifest review-selected.json
python work/review_batch.py plan-jobs --manifest review-selected.json
python work/review_batch.py integration
```

check 是用户将来主动执行的清单检查，不是 SolidWorks 验收。plan-jobs 只返回现有工作台规划任务，不运行任务，不生成模型。当前旧规划适配器即使对平板仍要求显式 radius/angle/K；缺值则保持 blocked，不塞虚构默认值。

## 保留的技术债与边界

- 批量审核清单已能转换为规划任务，但尚未替代桌面旧导出弹窗，也未接入具有原生重开证据的完整批量执行事务。
- 现有桌面批量确认仍是调用方声明，不构成身份认证；同一批混合工艺应逐件审核，不能假定共用 K 适合全部材料。
- 数量空间关联是候选算法；新窗口参数尚未验证，不能据此采购或投产。
- 稳定引用比较、特征检查表和整机摘要消费调用方的观察值；尚不能证明真实模型解析、配合、干涉和运动通过。
- 交付文件哈希与证据声明匹配不等于人工批准，production_approved 始终不由本轮代码自动设为 true。
- 可移植构建仍需目标解释器的完整 Tk/COM 依赖；没有构建、安装或冷启动验证。
